# Document UI contract inventory — checkout review draft

This is a scoped inventory of the document-facing UI, not the full Open WebUI compatibility manifest. Source: `packages/frontend/src` and `packages/backend/open_webui/mini_hermes/routes.py` in the working checkout. The paths below have prefix `/api/v1/mini-hermes`. The current V1 behavior is characterized here; the authorization publication race and V2 design remain open. Static observations do not establish actual browser traffic, proxy behavior, security isolation or V2 compatibility.

| Consumer | Request | Observed use and producer response | Evidence still needed |
|---|---|---|---|
| Workspace documents page | `GET /documents` | Array of document objects; page uses `id`, `filename`, `revision`, `sync`. | Browser/UI state, ACL filtering and errors. |
| Workspace | `POST /documents/upload` | Multipart field `file`; selects returned `id` after refreshing list. | Real upload, limits and failure/cancellation. |
| Workspace | `POST /documents/import-drive` | JSON `{url}`; returned document `id`. | Real Drive authorization and provider failures. |
| Workspace | `GET /documents/{id}/previews` | Up to 10 owned preview records with status, diff, operations and approval fields. | Consumer contract, permissions and status transitions. |
| Workspace | `POST /documents/{id}/previews` | JSON `{operations}`; XLSX sends `set_cell`, others send `replace_text`; response contains `id`, `status`. | Format allowlist, invalid operation and worker state tests. |
| Workspace and chat review | `GET /previews/{id}` | Fetch missing approval fields before commit; object contains base revision, checksums, patch hash, diff and filename. Producer checks preview owner and document read. | Live auth, revocation races and hash/backfill behavior. |
| Workspace and chat review | `POST /previews/{id}/commit` | Four approval fields in JSON; response includes `revision`, `sync_job_id`, `sync_status`. Route accepts optional `Idempotency-Key`; these consumers do not set it. | Explicit approval binding, retries, revoked permission and duplicate effects. |
| Workspace | `POST /documents/{id}/sync/retry`; `GET /drive/connect` | Retry sync then refresh; connect returns `authorization_url` used for browser navigation. | Drive conflict, auth and error behavior. |
| Workspace, chat review | `GET /previews/{id}/content` | Binary preview, with read permission and checksum check; used for viewing/downloading. | Binary MIME, corrupt objects, revoked permission and real browser behavior. |
| Workspace, chat review, file modal, personal files | `GET /documents/{id}/content?revision={number}` | Binary document bytes; absent revision selects current revision. UI turns bytes into viewer data or a download. | Revision 404, MIME/content-disposition, integrity and access tests. |
| Chat review | `GET /chats/{id}/previews`; `GET /chats/{id}/artifacts` | Polls arrays; artifacts failure is treated as empty. Skips temporary/local chat IDs. Uses revision and optional viewer/download URLs. | Live chat ownership, transport failure and UI polling state. |
| Chat review | `POST /previews/{id}/retry` | Failed preview returns to pending on success. | Stale revision, permissions, worker retry and error contracts. |
| File modal | `GET /source-files/{file_id}/document`, then fallback `GET /documents/{id}` | Tries source-file ID then document ID; fetches selected revision if resolved. Otherwise falls back to original file viewer. | ID collision, revoked access, invalid revisions and fallback isolation. |
| Document viewer shell | `GET /documents/{id}/revisions` | Array with revision number, created time, size and current flag; failed request is ignored. | Ordering, permissions, empty history and error UI. |
| Personal files menu | `PUT /chats/{id}/files/attachments` then `GET /personal/files?chat_id={id}` | Registers current file IDs, then consumes root folder, folders, documents, `can_write` and `in_chat`. Temporary/local IDs are rejected client-side. GET may register chat attachments and create a personal root in V1. | Side effects, live chat authorization, duplicate requests and V2 compatibility. |
| Personal files menu | `POST /folders`; `PUT /documents/{id}/folder`; `POST /documents/{id}/description/retry` | JSON folder name/parent or folder ID; UI updates its local state, refreshes after folder creation. | Folder permissions, race, recovery and error states. |
| Personal files menu | `PUT /chats/{id}/files` | JSON `{document_ids, folder_ids}` replaces selected chat document links. On failure UI reloads. | Authorization of all documents/folders, simultaneous changes and retry semantics. |

The existing producer-side ASGI tests and SQLite permission regressions cover selected operations only; see [test plan](08-test-plan.md). In particular, `GET /personal/files` is not a pure read in V1, and neither an HTTP method nor a function name suffices to classify a tool/route as retry-safe. The document UI must retain behavior through V2 integration unless a separately approved versioned change updates its consumers. Error details may be strings, objects, or validation arrays depending on the backend path; existing wrappers often pass `detail` directly to `Error`, so consumer-facing formatting must be characterized rather than assumed.
