# OpenAI proxy and direct-provider inventory — scoped Phase 0 draft

**Status:** Source-backed classification of the five unresolved `lib/apis/openai/index.ts` entries in the static route-pair index, with selected mocked consumer and ASGI producer tests. This is not a live provider or complete model-management audit. It extends [D07](07-open-webui-compatibility-manifest.md).

The frontend base `OPENAI_API_BASE_URL` is `${WEBUI_BASE_URL}/openai`; `main.py` mounts `openai.router` there. A URL supplied to the direct helpers is instead a browser-to-provider request. The two paths have different credentials, authorization checks, errors and operational ownership.

## Related model-management boundary

`getOpenAIConfig` and `updateOpenAIConfig` use admin-only `/openai/config` and `/openai/config/update`. The update form requires base URL, key and per-index config arrays/maps, normalizes key count, clears model cache and publishes a provider-config event. Provider catalog, download, status, load, unload, event stream and delete are separate admin routes under `/openai/models/{url_idx}/...`; `send_model_management_request` forwards provider HTTP status and body. The frontend model selector uses download acknowledgement `job_id` and polls status. A selected ASGI test verifies an unsupported provider is rejected with 400 before upstream traffic. Full provider-specific request/response schemas, side effects, SSE frames, retry and idempotency need owner review and tests. Download and deletion are external side effects; a local key alone cannot promise exactly-once.

`getModels` can combine server `/api/models` with browser direct connections from user settings when `enable_direct_connections` is enabled. This setting is off by default in `config.py` but may be changed. A V2 compatibility decision must state whether the direct branch remains available and how provider keys, browser origin/CORS and model-list provenance are represented. Do not silently treat direct models as server-authorized models or send their keys through AgentRuntime.

- `packages/frontend/src/lib/apis/openai/phase0-contract.test.ts` checks four mocked-fetch cases: indexed proxy discovery/error, direct discovery key, direct/server verification, and raw versus JSON chat completion response.
- `packages/backend/tests/test_v2_phase0_openai_proxy_contract.py` checks two ASGI cases with identity, config and connection discovery mocked: indexed lookup authorization/disabled state and unsupported model-management provider. No network provider call, real session, RBAC DB or V2 persistence was exercised.
- The existing D07 manifest and Phase 0 gate remain incomplete. Capture redacted live proxy/direct request examples and owner-reviewed golden error/stream fixtures before compatibility freeze.
